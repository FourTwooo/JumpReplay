# 1.7.0 发布前整理（2026-11-14）

## 本轮修改

- 首页溢出菜单移除“添加捕获快捷开关”，保留系统磁贴本身和已有添加状态；捕获监视窗补上与过滤、连接一致的灰色矢量图标。
- 小组件默认由 4 列 × 3 行改为 2 列 × 2 行，最低可调整尺寸设为 110dp × 48dp。实际可占格数由桌面决定，不能把目标格数理解为固定屏幕比例。
- 去掉组件品牌标题栏、长 Intent / URI 和重复操作提示，卡片突出用户自定义图标、昵称、页码，右上角保留配置入口。
- 按宿主提供的尺寸切换紧凑 / 较大卡片；很矮时保留单行昵称并隐藏页码。缩放、点击执行及各组件的独立动作选择继续沿用原链路。
- 已摆放组件的桌面位置、占格不会被强制修改，用户可拖动缩小或新添加。

## 验证状态

Debug / Release 构建通过；组件回归测试 3 项通过，验证缩放后动作身份和选择不变、卡片不展示 Intent 内容、不同组件互不影响、横竖屏宿主尺寸选择，以及 StackView 的 AT_MOST 测量不会使短昵称卡片收缩。Lint 0 错误、190 项警告。

后续真机已连接：OnePlus 6 / Android 10，序列号 f9b4ccf9。每次覆盖安装前已备份原 APK 和完整私有数据，逐文件读取验证 TAR；安装 dev.2、dev.3 均成功，未清空应用数据。首页菜单确认仅“过滤、连接、捕获监视窗”，三项均有图标。添加卡片预览显示 2×2；桌面实际布局仍由宿主决定，不能把预览格数当作全部桌面的保证。

真机发现并修复：尺寸判断错误地同时使用 MIN_WIDTH / MIN_HEIGHT，混合了横竖屏约束；短昵称导致原生 StackView 的 AT_MOST 子项测量收缩并把卡片分散。dev.3 按当前方向选择宽高，使用 API 24 已支持的 RemoteViews 设置方法撑满卡片。紧凑卡片实际显示正常，下滑从 WiFi 切换到 Bluetooth，点击确实进入系统蓝牙设置，未改动蓝牙开关。截图 / UI 树位于 audit-artifacts/v170-release-polish-phone-20261114。没有使用模拟器代替验收。

用户进一步明确期望为“中央完整卡片、后方上 / 下各有卡片、纵向轮转”的样式。当前原生 StackView 的单侧叠放不能视为已完成该要求；本次保留为可回退检查点，不宣称新样式已实现。精确轮转效果需先验证 RemoteViews / 桌面宿主的交互边界。

正式构建版本名仍为 1.7.0，当前测试构建为 1.7.0-dev.3。Release 产物目前未签名，发布时必须沿用项目原发布密钥；不能把 debug 候选包当成已签好的正式发布包。

## 发布前还应处理的已知项

1. **高：目标 App 的包可见性影响通信。** 上轮已在 API 33 复现：未声明主应用可见性的目标无法找到配置 Provider / Messenger；仅给测试夹具添加 queries 后通信成功，不等于真实目标已经修复。应作为优先兼容性修复项，不能要求用户修改第三方 App 的 Manifest。详见此前验证报告的 Android 13 补测。
2. **中：动作草稿没有独立的回收机制。** ActionEditorActivity.onSaveInstanceState 每次保存新文件，手工导入也创建临时载荷，成功保存或取消后缺少对应清理。长期编辑含大快照的动作会积累占用。应区分临时草稿和永久快捷方式载荷后再回收，不能直接清空 shortcut_payloads。
3. **中：部分新页面文案仍硬编码中文。** 图标选择菜单、动作操作菜单、组件配置说明等未全部使用字符串资源，英文 / 日文界面会出现中外文混用。应按已有本地化方式补齐。

上述三项是本轮核对后的待处理问题，没有混入菜单和尺寸修改中，也没有标记为已解决。
