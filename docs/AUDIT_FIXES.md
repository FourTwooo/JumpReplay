## 验证与真机测试

使用 JDK 17、已配置 Android SDK：

```powershell
./tools/Build-Audit.ps1
```

脚本编译 Debug、unsigned Release、两个模块的 Android 测试 APK，并运行两模块单元测试和 Lint。
编译 Android 测试 APK 不等于已在设备执行测试。本轮不自动安装/替换手机应用，不改 LSPosed 作用域或 Root/Shizuku 授权。

2026-11-11 最终验证：Debug/unsigned Release 及两模块 Android 测试 APK 编译成功；
单元测试 **67/67 通过，0 跳过**；两模块 Lint **0 Error、0 Fatal**（主应用 157 条 Warning，模板 30 条 Warning）。
实际主 APK 内的模板与本次构建模板 SHA256 一致，实际二进制 Manifest 恰有 64 个协议槽位，无 dewulink。
回退脚本在独立测试仓库验证通过，包括新旧分支切换和存在未提交内容时拒绝覆盖。

真机测试重点：

1. 既有作用域应用、预装系统应用及 LSPatch：上报与配置写入继续可用。
2. 悬浮窗局部开关、主页全局开关、返回主页、旋转和服务断线重连。
3. 冷启动首批记录；后台持续捕获后返回主页；历史翻页、搜索、删除和清空。
4. `tel:`、`mailto:`、`+`、百分号、中文、数组/嵌套 Extra、大记录和失败后重试。
5. Root/Shizuku 启动、动态参数快捷方式、旧快捷方式和连续打开不同快捷方式。
6. HTTP/HTTPS 禁用热更新、无效自定义 Hook 后其他规则继续工作。
7. 64 协议生成、split 路由、URI 文件授权和多个拦截器转发。

单个 Intent 带有不可持久化的 Binder/文件描述符时，保存错误会明确报告，并保留可表示的字段；不会声称普通 URI 能完整还原这些进程资源。

发件箱在 Hook 线程快速入队，约 50ms 后由后台短批次落盘，发送前必先落盘。目标进程在这段尚未落盘的窗口内被强杀，仍可能丢失内存事件；已落盘记录支持断线/ACK失败重试，不作零丢失承诺。
